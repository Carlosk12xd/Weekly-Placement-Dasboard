# October 21: class window, October rollover, weekly cross-checks, Friday decks

| Area | Change |
| --- | --- |
| Weekly History | Only the last week of June Y-1 .. last Friday of September Y is kept. Out-of-window columns (e.g. the March-April 2026 columns copied into the 2027 workbooks), same-day duplicates (`07/10/2026_2`..`_4`) and empty `Column1` placeholders are removed; ZOHO_DATA rows likewise. |
| Tracking | A class is tracked through September 30 of its graduation year (was graduation + 90 days, which missed the last Friday of September). `tracking_grace_period_days` is no longer used. |
| Report class | People receive the class named by the October-September report year (October 2026 -> Class of 2027). The next class, collected from late June, is archived only. Replaces the Pi's hard-coded `cohort.id != "2027"` skip. |
| Next class | A class missing from cohorts.yml is derived from the latest one; its workbooks are created from the previous class's on the first run, with years in sheet names and titles moved forward and history cleared. |
| % Placed | Program reports recompute Class Size and % Placed for every column (leadership already did). |
| Cross-checks | core/report_checks.py checks every saved workbook against the SQL it was built from and its own arithmetic before promotion or delivery; visualization_test/checks.py checks each dashboard against its source before screenshots. |
| Friday decks | core.daily_runner runs visualization_test on Fridays with the run's checked snapshots (test recipients only). |

Update October 28: the full-time population now also uses the graduation term (actual,
else expected). Students graduating August Y-1..June Y are counted in Class Y whatever
their class_of; students graduating after June Y move to a later class; graduates from
before August Y-1 stay with their earlier class. A read-only query warns about anyone
still kept outside the window (students enrolled past their term).

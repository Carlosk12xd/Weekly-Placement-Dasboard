# Changes made 2026-07-23 (for the Friday 2026-07-24 10am run)

Scope was deliberately narrow: the summary-sheet changes only. Career Director program
reports, the email flows, and `daily_runner.py` were **not** touched.

---

## 1. `LeadershipReport/update_overall_report.py`  (the only code file changed)

**Added** near the other status constants:

```python
STATUS_NO_INFO = "No Recent Information Available"
PCT_FORMAT = "0.00%"
COUNT_FORMAT = "0"
```

**Added** `SUMMARY_HEADERS` — the new 11-column layout:

```
Program | % Placed | Offers Accepted | Still Seeking | Not Reported | No Info
        | Int'l | Not Seeking | Total | % NS** | % Null
```

The old layout was 10 columns (`A2:J17`) with `No Info*` and no `Not Reported`.

**Replaced** `update_summary_sheet(ws, rows)` with `update_summary_sheet(ws, rows, byprog_ft)`.
The old body is still in the file, renamed `_unused_update_summary_sheet`, and is no longer
called. What changed and why:

- The summary SQL lumps `Not Reported` and `No Recent Information Available` into a single
  `no_info` column, so it physically cannot separate them. That is why the summary's % Placed
  disagreed with page 3. The new version takes Offers Accepted / Still Seeking / Not Reported /
  No Info from `byprog_ft` (the per-program SQL, already fetched in `main`), which keeps them
  apart, and uses the summary SQL only for Int'l / Not Seeking / Total.
- Every value comes from SQL. Nothing is read back out of the sheet, so re-running on an
  already-updated workbook produces an identical result.
- The Total row is now live Excel formulas (`=SUM(...)`, `=IFERROR(...)`) so the overall rate is
  pooled rather than an average of the 14 program rates.
- Four footnote rows are written below the table (rows 18-21).
- Summary columns are auto-widened so all 11 headers are readable.

**Changed** one line in `main()`:

```python
update_summary_sheet(ws, summary_rows)              # before
update_summary_sheet(ws, summary_rows, byprog_ft)   # after
```

`reset_workbook_view_to_a1` was already present in the live file and is unchanged.

## 2. `config/cohorts.yml`

The 2027 cohort's four Box addresses were the placeholder examples copied verbatim from the
comment block at the top of the file, so 2027 uploads were not landing in a real folder. They now
point at the same folders as 2026.

## 3. Not changed

`core/daily_runner.py`, `LeadershipReport/email_overview_report.py`,
`ProgramReports/email_program_reports.py`, and everything under `ProgramReports/`.
Routing already did what was wanted — both email flows gate on `cohort.id != "2027"`, so 2026
goes to Career Directors and 2027 is Box-only. No edit was needed.

# How to roll back

## IMPORTANT: restore the workbooks too, not just the .py

After the Friday run, `Reports/*.xlsx` will have been rewritten to the 11-column layout.
The old `update_summary_sheet` validates that the sheet has exactly the old 10 headers and
raises `RuntimeError: Summary headers missing or mismatched` if they differ. So restoring only
the Python file against an already-converted workbook **will crash the next run**.
Always restore both together.

```bash
cd /home/bccdatapi/raspberryPI/PlacementRateReports

# 1. code
cp LeadershipReport/update_overall_report.BACKUP-2026-07-23-1659.py \
   LeadershipReport/update_overall_report.py

# 2. workbooks (required -- see note above)
cp LeadershipReport/Reports/backup_20260723/*.xlsx LeadershipReport/Reports/

# 3. cohort config (only if you also want 2027 back on the placeholder Box addresses)
cp config/cohorts.BACKUP-2026-07-23-1702.yml config/cohorts.yml
```

Rolling back the workbooks loses any weekly-history column added after 2026-07-23 16:59.

## Verify a rollback

```bash
. /home/bccdatapi/raspberryPI/raspberrypi/bin/activate
python3 -c "
from openpyxl import load_workbook
ws=load_workbook('LeadershipReport/Reports/2026_weekly_placement_report.xlsx')['Summary - Full Time']
print(ws.tables['summary'].ref)   # A2:J17 = rolled back, A2:K17 = new layout
"
```

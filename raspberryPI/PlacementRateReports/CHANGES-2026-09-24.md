# September 24: unattended-run readiness

The existing workbook-to-dashboard-to-PDF-to-email path remains implemented.
This update addresses operational failures observed while reviewing that path.
It does not install or activate the code on the Raspberry Pi.

## Behavior changes

| Area | Updated behavior |
| --- | --- |
| Configuration | Reject quoted boolean strings, duplicate cohort years, invalid modes/dates and negative grace days before report work. |
| Settings | Read each report directory's .env into a separate mapping. Explicit process settings override it. SQL/mail use the selected group's settings; offline runs skip .env entirely. |
| Standalone builders | Preserve OUTPUT_PATH from the selected settings mapping when no explicit staged output path is passed. |
| Report selection | Runner and readiness checks share one enumeration of existing audiences/paths; the original director dictionary remains authoritative and unchanged. |
| Partial failures | Missing source files or corrupt ledgers fail only the affected bundle. Corrupt ledger bytes remain intact. Missing PDF converters hold required-PDF human mail while valid archive routes can continue. |
| Execution records | Persist start, current bundle, results and completion/failure. Keep every invocation plus latest-invocation and latest-eligible-report summaries. Overlap records do not replace active summaries. |
| Readiness | core.doctor checks local prerequisites, input containers, template fingerprint, storage and setting presence without SQL/SMTP or run-state writes. It does not authenticate or benchmark the Pi. |
| Status | core.status reports bundle/artifact/SMTP states and can verify saved hashes. It displays preview mode explicitly and never automatically resends or repairs anything. |

## Commands

From PlacementRateReports on the Pi, after installing requirements:

```bash
python -m core.doctor --cohort 2027
python -m core.status --last-report --verify
```

For the supplied fixture:

```bash
python -m core.doctor --offline --cohort 2027 --date 2026-08-21 \
  --source-root tests/fixtures --run-root /tmp/bcc-fixture-preview
python -m core.daily_runner --offline --cohort 2027 --date 2026-08-21 \
  --source-root tests/fixtures --run-root /tmp/bcc-fixture-preview
python -m core.status --run-root /tmp/bcc-fixture-preview --last-report --verify
```

Use `--json` with doctor/status for machine-readable results. The daily runner
still uses the original Friday/month-end calendar and global process lock.
`delivery_enabled: false` remains the release default. Existing cron is unchanged.

## Evidence and limits

All 29 regression tests passed: the original 14 checks plus 15 operational tests.
The settings parser, SQL connector and SMTP server were mocked where exercised.
A real LibreOffice/Poppler run through the revised runner produced Finance's
three-page PDF and Healthcare's workbook-only report: two XLSX bundles, one PDF,
four saved MIME messages, all hashes verified. A read-only readiness check passed
for the complete 12-bundle offline fixture. All 28 original production workbooks
and the director routing dictionary match the inspected originals.

The previous September 23 full render remains evidence for the unchanged PDF
layout: 11 PDFs, 50 pages and 25 email previews. It was not repeated in full during
this operational update. Live authentication, recipient validation with staff,
SQL data correctness, target-Pi resources, cron execution and Box/Zoho ingestion
still require the actual Pi. No real email was sent and no live SQL was queried.

`READINESS_PLAN.md` records the pre-edit anchors. `SOURCE_MAP.md` gives exact current
function lines. `VALIDATION_RESULTS.json` separates the two verification stages.
The settings parser follows the dependency's documented
[dotenv_values API](https://github.com/theskumar/python-dotenv#load-configuration-without-altering-the-environment).
